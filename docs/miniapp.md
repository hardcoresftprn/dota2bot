# Telegram Mini App

Production: https://dota2bot.sdsbtw.workers.dev/app/

Открывается через «Открыть» в меню @dota2sds_bot или `/app`. В группах кнопка ведёт в личный чат: Telegram разрешает кнопки Web App в личных чатах.

## Возможности

- **Мета:** пять позиций, девять вариантов ранга, пять героев по рейтингу StatsDota, победы, пики, число матчей, карточки и ссылки на источник. Период, патч и предупреждения об устаревании или расширенной выборке видны в интерфейсе. Кеш общий с `/meta`, один час.
- **Патчи:** до 20 сохранённых разборов с официальными ссылками Valve. Чтение ленты не создаёт рассылок. Патчи, сохранённые только как рассмотренные ID без разбора, в ленте не появляются.
- **Моё:** любимая позиция и ранг. В Telegram сохраняются в D1 для проверенного пользователя, в обычном браузере — на устройстве. Статус рассылки относится к личному чату; групповая подписка управляется отдельно.

## Устройство

`cloudflare/public/app/` публикуется как Workers Static Assets в существующем Worker. Дополнительный сервер, сборщик фронтенда или платный сервис не нужен. GitHub → Cloudflare Builds использует прежнюю команду `npx wrangler deploy` из каталога `cloudflare`.

`GET /api/meta?position=1&rank=all` и `GET /api/patches` отдают публичные данные. `GET/POST /api/profile` требуют исходную строку `Telegram.WebApp.initData` в заголовке `X-Telegram-Init-Data`. Сервер проверяет HMAC-SHA256 по [документации Telegram](https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app), срок подписи до одного часа и ALLOWED_USER_IDS, если список настроен. ID берётся только из проверенных данных Telegram. Токен бота на фронтенд не попадает. Ключ настроек в таблице meta: `miniapp_prefs:<telegram_user_id>`; значение содержит только позицию и ранг.

После истечения сессии нужно закрыть и заново открыть приложение через меню бота. `initDataUnsafe` не используется для авторизации. При ограничении общего IP Cloudflare публичные данные OpenDota могут загружаться напрямую через поддерживаемый CORS API; Telegram initData в источник не передаётся. HTML разборов очищается до разрешённых тегов и официальных HTTPS-ссылок. Ответы профиля не кешируются.

Портреты используют канонические имена Valve и Steam CDN. Карта ID → изображение находится в `cloudflare/src/hero-images.js`; для новых героев её можно обновлять по официальному списку Valve. Отсутствие портрета не скрывает статистику.

## Проверка и запуск

```sh
cd cloudflare
npm test
npx wrangler deploy --dry-run
npm run db:local
npm run dev
```

Локальный адрес: http://127.0.0.1:8787/app/. Локальная база отдельная от production. Без Telegram работает гостевой режим.

После первого деплоя меню настраивается прежним скриптом:

```sh
npm run telegram:setup -- --url https://dota2bot.sdsbtw.workers.dev
```

Скрипт читает локальные игнорируемые `.env`/`.dev.vars`, добавляет `/app` и кнопку меню. Секреты и webhook менять не нужно.

## Контрпики

Выбор 1–5 врагов. Позиция берётся из сохранённых настроек «Моё», отдельно от временного фильтра вкладки «Мета».

Источник: публичная страница [StatsDota counter picker](https://statsdota.com/en/counters/team) (каталог, частота позиций, патч) и `/api/counter-cells` (парные матчапы). Задание GitHub Actions `.github/workflows/counters.yml` каждые 6 часов читает JSON из публичных props без исполнения скриптов и обновляет `cloudflare/public/counter-data.json`. Обычная публикация Cloudflare доставляет файл в Static Assets. Worker читает этот файл, кеширует в D1 на час, при ошибке повторяет через 5 минут. Прямое чтение страницы из Cloudflare не используется: её поток там обрывался. После 8 часов без обновления данные отмечаются как устаревшие. Сохранённые данные доступны до двух суток с предупреждением. Изменение формата источника приводит к использованию проверенного кеша или явной ошибке.

Ячейка `cells[enemy_id][candidate_id]`: преимущество кандидата в процентных пунктах, его винрейт против врага, число матчей. Кандидаты не заняты врагом, имеют ≥15% игр на выбранной позиции и ≥150 матчей против **каждого** врага. Порядок — среднее преимущество, при равенстве — минимальная выборка пары. Недостающие пары исключают кандидата. Карточки показывают все пары, включая отрицательные.

Данные пар общие по всем рангам и позициям; позиция фильтрует только пул кандидатов. Ранг профиля не фильтрует матчапы. Синергия и винрейт всей связки не оцениваются. Среднее преимущество не является вероятностью победы. Показаны дата получения и патч источника, точный период матчей endpoint не сообщает.

`GET /api/counters` — каталог; `GET /api/counters?enemies=1,12&position=3` — пять вариантов для позиции 3.
