# sds DOTA: Steam, сборки и анализ

## В приложении

- **Мета:** текущие сильные пики по позиции и рангу. Карточка героя открывает его сборку.
- **Контрпики:** выберите 1–5 врагов. После подбора показаны герои и предметы с объяснением механики, момента покупки и ограничений. Предметы доступны даже при сбое статистики матчапов.
- **Сборки:** найдите героя; показаны популярные покупки по четырём стадиям. В средней и поздней игре скрыты рецепты и базовые компоненты. Выбранные в контрпиках враги используются для ситуационных советов. При изменении врагов сборка обновляется при возвращении на вкладку.
- **Анализ:** Dota ID, SteamID64 или числовая ссылка `https://steamcommunity.com/profiles/…`; переключатель «Матч» принимает ID матча. Из состава команд можно перейти к профилю игрока, из истории игрока — к матчу.
- **Моё:** вход через Steam, отвязка и переход к своей статистике. Привязка доступна только при открытии из Telegram.
- **Патчи:** кнопка с номером патча в верхней панели открывает прежнюю ленту разборов.

## Steam

Используется [официальный Steam OpenID](https://partner.steamgames.com/doc/features/auth#website). Steam Web API key для входа не требуется. Пароль вводится только на сайте Steam; приложение его не получает.

`POST /api/steam/start` требует подписанные Telegram initData, проверяет срок подписи и allowlist. Генерируется случайное одноразовое состояние на 10 минут, привязанное к Telegram ID. Повторный запуск отменяет предыдущую ссылку. Steam открывается во внешнем браузере; после входа вернитесь в Telegram, откройте «Моё» и нажмите «Проверить подключение». Проверка также выполняется при возвращении фокуса или открытии вкладки.

Callback проверяет endpoint, namespace, identity/claimed_id, return_to, подписанные поля и nonce, затем подтверждает подпись прямым HTTPS-запросом к Steam. В соответствии с документацией Steam допустимы HTTP- и HTTPS-строки claimed_id; это идентификатор, по нему не выполняется сетевой запрос. Проверка всегда идёт на фиксированный HTTPS endpoint. Форма передаётся строкой с явным `application/x-www-form-urlencoded;charset=UTF-8`, перенаправления не выполняются. Привязка записывается транзакцией только при ещё действующем состоянии. Повторный callback и callback после отвязки не восстанавливают привязку. Telegram ID из параметров callback не принимается. Привязка хранит только Telegram ID, SteamID64 и время. Токены Steam не сохраняются.

## Источники и ограничения

[OpenDota](https://opendota.apidocumentation.com/) предоставляет публичную историю игрока, исходные данные матча и покупки профессионалов. Закрытая история, задержка индексации, неразобранный реплей, анонимизация и сбои источника показаны явно. Недоступные показатели не заменяются нулями.

Сборки используют `/heroes/{id}/itemPopularity`: числа означают покупки, а не винрейт или долю матчей. Это набор популярных вариантов по стадиям, не обязательная последовательность покупки. Endpoint не сообщает точный период и патч выборки, не фильтруется по рангу или позиции. В приложении указано время получения, устаревшие ответы помечены. Каталог названий, стоимости и изображений обновляется из [OpenDota dotaconstants](https://github.com/odota/dotaconstants) скриптом `npm run data:items` и существующим заданием GitHub Actions раз в 6 часов.

Контрпредметы — отдельный справочник механик в `cloudflare/src/builds.js`, не статистический рейтинг предметов. Приоритет учитывает позицию и количество выбранных врагов. Рекомендация не проверяет автоматически инвентарь конкретного противника. Изменение игровых механик требует обновления правил; автоматическое обновление каталога не обновляет текст правил.

Оценка признаков смурфа берёт до 30 последних доступных рейтинговых All Pick матчей длительностью от 15 минут, среди последних 100 матчей источника. Turbo и обычные матчи исключены. При менее 20 подходящих матчах данных недостаточно. Признаки: ≥75% побед на ≥20 матчах; средний KDA ≥5 при наличии всех необходимых полей минимум у 20 матчей; меньше 300 известных OpenDota матчей учитывается только вместе с другим признаком. Два признака дают повышенную оценку, один — отдельный признак. Это прозрачная эвристика, не обученная модель, не вероятность смурфа и не установление нарушения. Открытая история не равна полной истории или возрасту аккаунта.

Кеши в D1: профиль 15 минут, матч 30 минут, покупки героя 6 часов. При сбое доступен явно помеченный кеш до суток. Блокировки защищают одновременное обновление одного ключа. Серверный бюджет ограничивает OpenDota до 45 запросов в минуту и 2800 в сутки. Если общий исходящий IP Cloudflare ограничен самим OpenDota (429), приложение использует поддерживаемый публичный CORS API из браузера посетителя. В этом случае действуют лимиты OpenDota для посетителя; результат кешируется только в памяти вкладки (до 20 записей). Ответ 429 от самого посетителя не повторяется автоматически. Собственный серверный лимит приложения не включает этот резервный путь. Telegram initData, секреты и cookies в OpenDota не передаются. Расчёты сервера и браузера используют один `public/app/dota-core.js`. Ключ OpenDota не требуется.

## Обновление существующего Worker

Работайте в каталоге `cloudflare`:

```sh
npm test
npm run db:local
npx wrangler deploy --dry-run
```

Для публикации необходим доступ к существующему аккаунту Cloudflare. Сначала примените добавочную схему, затем обновите Worker:

```sh
npx wrangler login
npm run db:remote
npm run deploy
```

`schema.sql` добавляет `steam_accounts` и `steam_auth`, не удаляя подписки, историю патчей и очередь отправки. Без применения схемы Steam работать не будет. Локальная база независима от рабочей.

Для настройки только кнопки меню без изменения webhook и секретов:

```sh
npm run telegram:setup -- --url https://dota2bot.sdsbtw.workers.dev --menu-only
```

Скрипт проверяет результат через `getChatMenuButton`. Для отдельной кнопки «Открыть» в профиле/списке чатов нужен **Main Mini App**: откройте @BotFather → `/mybots` → @dota2sds_bot → Bot Settings → Configure Mini App / Main Mini App и укажите:

```text
https://dota2bot.sdsbtw.workers.dev/app/
```

Названия пунктов зависят от клиента и версии BotFather. [Документация Telegram о Main Mini App](https://core.telegram.org/bots/webapps#launching-the-main-mini-app) отличает эту кнопку от `setChatMenuButton`; Bot API не предоставляет настройку Main Mini App.

## Проверки

`cloudflare/test/dota-features.test.js` проверяет границы ID, подписи и изоляцию Telegram, подмену ответа Steam, истёкшие/повторные/отменённые ссылки, транзакционную привязку, корректное определение стороны игрока, недостающие поля матча, выборку оценки смурфа, кеширование, бюджет API, предметы и сборки. Тесты используют отдельную SQLite в памяти и подменяют внешние ответы. Реальный вход пользователя в Steam требует отдельной проверки после публикации.

## Публикация 7 ноября 2026

Схема Steam применена к существующей D1, приложение опубликовано на рабочем Worker. Production-проверка выявила 429 от OpenDota на общем исходящем IP Cloudflare; добавлен публичный CORS-режим с общей логикой расчётов и отдельными тестами. Кнопка меню «Открыть» подтверждена через Telegram Bot API. Main Mini App включён через BotFather с подтверждением «Success! Mini App settings updated»; Telegram Bot API возвращает `has_main_web_app: true`. Проверен реальный запуск опубликованного приложения внутри Telegram, а также загрузка сборки, матча и профиля через рабочий HTTPS-адрес. Изменения опубликованы в `origin/main`.

## Диагностика подключения Steam

Страница ошибки различает отмену пользователем, истечение/замену состояния, несовпадение обязательных полей, сетевую ошибку, HTTP-отказ Steam и неподтверждённую подпись. Показывается короткий код проверки. В D1 `meta` по ключу `steam:last_failure` хранится только время, код, HTTP-статус или имена проваленных проверок — без URL callback, состояния, подписи, Steam ID, Telegram ID, cookies и секретов. Эта запись помогает сопоставить реальную попытку после публикации с серверной причиной. Успешный ответ Steam по-прежнему обязателен для привязки.
