# sds DOTA — Telegram-бот и Mini App для Dota 2

Бот каждые 10 минут проверяет **официальные** патчи Dota 2 и новости Valve в Steam.
Присылает короткие разборы на русском с главными изменениями, оценкой влияния на
игру и рейтинговые матчи и ссылкой на оригинал. Работает в личке и общем чате.

**Рабочий бот: [@dota2sds_bot](https://t.me/dota2sds_bot).**
Нажмите Start для подписки, `/latest` — для последнего разбора.
`/meta` показывает мету для пяти позиций; позицию и ранг можно выбрать кнопками.
Размещён на Cloudflare Workers + D1; компьютер владельца может быть выключен.
Для общего чата администратор отправляет `/start@dota2sds_bot`.
Токен хранится в Cloudflare Secrets и исключён из репозитория.

## Что входит

- Крупные игровые патчи, буквенные балансные патчи, выпущенные новые герои,
  изменения рейтинга и подбора матчей.
- Косметика, результаты турниров, обычные исправления багов и анонсы будущих
  релизов не входят в автоматическую рассылку.
- Один канонический ID патча на оба источника. История и очередь отправок
  сохраняются в базе; перезапуск не создаёт повторную рассылку.
- Подписка каждого чата независима. Новый подписчик получает новые события,
  старые публикации при первом запуске не рассылаются.
- Без AI-ключа бот бесплатен: выбирает конкретные русские изменения Valve и
  добавляет осторожную оценку влияния по типу изменений. Это алгоритмический
  отбор, а не экспертный мета-анализ. Для отдельных англоязычных новостей без
  структурированных примечаний даёт тему обновления и ссылку без выдуманных деталей.
- Необязательный OpenAI API делает содержательные русские разборы и лучше
  определяет значимость новостей; API оплачивается отдельно. Один разбор
  сохраняется и используется для всех подписчиков. При ошибке AI используется
  базовая сводка Valve. Модель задаётся через `OPENAI_MODEL`.

## Бесплатный сервер

Текущий вариант — **Cloudflare Workers Free + D1**. Версия в папке `cloudflare`
получает команды Telegram через webhook и проверяет Valve/Steam по расписанию.
Подписки и история сохраняются в D1. Постоянно включённый компьютер не нужен.
На 6 ноября 2026 года [Workers Free](https://www.cloudflare.com/products/workers/)
доступен без карты и включает 100 000 запросов в сутки;
[D1 Free](https://developers.cloudflare.com/d1/platform/pricing/) включает базу
с лимитами по строкам и хранилищу. Задания обрабатывают очередь небольшими порциями,
чтобы укладываться в бесплатные ограничения.

Пошаговый запуск: **[docs/cloudflare.md](docs/cloudflare.md)**.
Python-версия ниже остаётся для локального запуска и серверов с Docker.
Инструкция Northflank сохранена как прежний вариант; в текущем запуске он не используется.

## Создать бота в Telegram

1. Откройте [@BotFather](https://t.me/BotFather), отправьте `/newbot`.
2. Задайте название и уникальный username с окончанием `bot`.
3. Сохраните выданный токен в `TELEGRAM_BOT_TOKEN` в локальном `.env` или секретах
   хостинга. Не загружайте `.env` в GitHub.

Для работы в личке каждый друг открывает бота и нажимает **Start**.
Для общего чата добавьте бота и отправьте `/start@имя_бота` от администратора.
Бот может оставаться с включённым Privacy Mode. Для проверки администраторов
через `getChatMember` надёжнее назначить бота администратором группы; лишние права
на удаление сообщений или блокировки ему не нужны.

## Локальный запуск

Python 3.11+; проверено на Python 3.14. macOS/Linux.

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env
chmod 600 .env
```

Заполните `TELEGRAM_BOT_TOKEN` в `.env`, затем:

```sh
.venv/bin/python -m dotabot
```

Пока процесс работает и компьютер подключён к сети, бот отвечает и проверяет
новости. При выключении компьютера он останавливается. В локальном режиме данные
хранятся в `data/bot.sqlite3`. Не удаляйте эту папку, если нужна история подписок.

Можно посмотреть реальный последний патч без Telegram и без базы:

```sh
.venv/bin/python -m dotabot --preview
```

Если задан `OPENAI_API_KEY`, preview тоже использует AI. Уберите ключ для
полностью бесплатного просмотра.

## Docker

После заполнения `.env`:

```sh
docker compose up -d --build
docker compose logs -f bot
```

Именованный том `bot-data` сохраняет SQLite при замене контейнера.
Не выполняйте `docker compose down -v`, если нужна сохранённая история.
Для сервера с PostgreSQL задайте `DATABASE_URL`: локальный том тогда не используется.

## Команды

| Команда | Действие |
|---|---|
| `/start` | Подписать текущий чат |
| `/stop` | Отписать текущий чат и отменить ожидающие отправки |
| `/latest` | По явному запросу показать последний сохранённый разбор |
| `/meta` | Мета пяти позиций; `/meta 2 legend` — мид на Легенде |
| `/status` | Показать подписку и время последних успешных проверок |
| `/help` | Справка |

В группе включать и выключать подписку может только администратор. По умолчанию
подписаться может любой; `ALLOWED_USER_IDS` ограничивает использование указанными
Telegram user ID. В группе проверяется ID автора команды. Друзья, которые
получают рассылку только в общей группе, не обязаны быть в списке.

Подробности: [источник меты и свежесть данных](docs/meta.md),
[как менять название, аватарку и описание](docs/bot-profile.md).

## Конфигурация

| Переменная | Значение по умолчанию |
|---|---|
| `TELEGRAM_BOT_TOKEN` | Обязательно для запуска бота |
| `DATABASE_URL` | Пусто — SQLite; заполнено — PostgreSQL |
| `DB_PATH` | `./data/bot.sqlite3` |
| `CHECK_INTERVAL_SECONDS` | `600`, минимум `60` |
| `OPENAI_API_KEY` | Пусто — базовая сводка без API-расходов |
| `OPENAI_MODEL` | `gpt-4.1-mini`, можно изменить на доступную совместимую модель |
| `ALLOWED_USER_IDS` | Пусто — всем; иначе ID через запятую |
| `PORT` | `8080`, HTTP-проверка работоспособности `/healthz` |

## Доставка и ограничения

На одной базе работает один процесс бота: защита от второго экземпляра через
файловую блокировку SQLite или advisory lock PostgreSQL. У сервиса должна быть
**одна реплика**. Для обновления используйте стратегию остановки старого процесса
перед запуском нового, чтобы избежать конфликта long polling.

В Steam читается только `steam_community_announcements` приложения 570. При сбоях
источники проверяются независимо. После простоя Steam догружается по страницам
с перекрытием в сутки, а список патчей проверяется полностью. При изменении уже
обработанной публикации тот же патч повторно не рассылается. Для неизвестной
будущей структуры примечаний нужна правка парсера; устаревшую успешную проверку
видно через `/status`.

У Telegram нет ключа идемпотентности для `sendMessage`. Если сеть оборвалась после
отправки запроса или процесс завершился между отправкой и подтверждением,
невозможно одновременно гарантировать отсутствие потери и отсутствие дубля.
Бот отдаёт приоритет отсутствию дублей: помечает такую доставку `uncertain` и не
повторяет её автоматически. Пропущенный разбор можно запросить через `/latest`.
Подтверждённые ограничения Telegram 429 безопасно повторяются после `retry_after`.

Фильтр базового режима использует признаки в тексте: для необычно оформленной
новости возможен пропуск или неверная классификация. AI-режим лучше учитывает
контекст, но тоже не заменяет оригинальные примечания. Рекомендации о влиянии
сформулированы как предположения, а не статистика побед.

`/healthz` проверяет, что процесс отвечает; состояние источников смотрите в `/status`.
Логи HTTP-клиента отключены, чтобы токен Telegram не попадал в URL в логах.

## Проверка

```sh
.venv/bin/python -m unittest discover -s tests -v
```

Тесты покрывают подписки, дедупликацию двух источников, перезапуск, атомарную запись
в базу, сбои и лимиты Telegram, права группы, пагинацию Steam, HTML-экранирование,
схему AI и резервную сводку. Для проверки PostgreSQL используйте **отдельную
пустую тестовую базу**: задайте `DOTABOT_TEST_DATABASE_URL` и запустите ту же команду.
Тесты очищают таблицы этой базы после каждого сценария.
